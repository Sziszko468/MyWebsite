# Browser audits

The scripts the PROMPT 11 audit was run with (results: `docs/technical-audit.md`). They drive a real Chrome through Playwright against the **built** site, so build first (`npm run build`). They are not part of `npm test`, and Playwright and axe-core are not dependencies of this project: install them anywhere (`npm i playwright-core axe-core` in a scratch folder) and point the scripts at them.

```bash
export AUDIT_PLAYWRIGHT=/path/to/node_modules/playwright-core   # or `playwright`
export AUDIT_AXE=/path/to/node_modules/axe-core/axe.min.js
```

They use the system Chrome (`channel: 'chrome'`, with `--ignore-gpu-blocklist`, so a real GPU is used if there is one). Each starts its own static server (`serve.cjs`: brotli/gzip, applies `dist/_headers`, so the real Content-Security-Policy is in force) and needs no setup. On Git Bash for Windows set `MSYS_NO_PATHCONV=1` when an argument starts with `/`.

| Script | What it checks |
| --- | --- |
| `seo-browser.cjs` | Every built page loaded under the production CSP: no console errors or CSP violations, the head the build wrote is still the head after the app ran, in-app navigation and the language switch keep the head in step, 404/cart say `noindex`, the intro opens on the home page only. |
| `audit-a11y.cjs` | axe-core (WCAG 2.0/2.1/2.2 A and AA, best practice) on every page × language × theme (injected through the protocol, so the page keeps its real Content-Security-Policy), plus structure: one `h1`, heading order, alt text, link and button names, labels, duplicate ids. |
| `audit-keyboard.cjs` | (Noisy since the header became sticky: it keys controls by position and looks for the ring inside the control's own box, so it reports header links as "never focused" and cards as "without a ring" falsely; prefer `audit-keyboard-strict.cjs`.) A Tab-only walk of the key pages: the skip link, every control reachable, no trap, focus visible, not covered by a sticky bar (WCAG 2.4.11), target size (2.5.8). `--w --h --mobile=1` for other sizes. |
| `audit-matrix.cjs` | Layout at the required viewports (portrait and landscape), languages and themes: sideways scrolling, elements outside the viewport, tiny text and targets, upscaled images, console errors. `--sizes=1920x1080,390x844 --langs=en,hu --themes=dark,light`. |
| `audit-shop3.cjs` | (PROMPT 09.1) axe-core on the **interactive** states of Shop 3.0 that `audit-a11y.cjs` cannot reach: the comparison table with a feature explanation open; the phone switcher with each tab, a group open and the two-package mode (with and without "only the differences"); a package page and the FULL EXPERIENCE page; the configurator at every step and in its error states (nothing chosen on a required question, a too short description, empty contact details; it is never sent). 1440×900, 390×844 and 320×640 in both themes by default; driven by English labels. Found three real defects, now fixed: Carbon Black text on the Cobalt Grow tab (3.95:1), the same on the Graphite Care tab in the light theme (1.49:1) and a tab whose `aria-controls` named a panel that is not there in the two-package mode. `--sizes --langs --themes`; exit code 1 on any finding. |
| `audit-admin.cjs` | The **administration** (`/admin`, PROMPT 13), against a running backend that serves the built site (`STATIC_DIR`) and an administrator of a **throw-away database**: every screen × viewport (1920×1080 … 320×640) × theme × language for sideways scrolling, elements outside the viewport, targets under 24 px, controls without a name, one `h1`, and axe-core; the delete dialog (focus starts on the safe button, Tab stays inside, Escape cancels and returns focus) and the phone's "More" sheet. Since PROMPT 13.1 it also covers the project list, a new project, the settings, the editor of the first project (all seven tabs), the picture chooser (Escape closes it) and the website-texts screen with a row open. Signs in once (the sign-in is rate limited). `--base --email --password --sizes --themes --langs --out`; exit code 1 on any finding. |
| `audit-ai.cjs` | (PROMPT 16) **Control Room AI** against a running backend whose model is the local stand-in (set-up as in `tools/e2e/ai-journey.cjs`; throw-away database; start the backend with `RATE_LIMITS=false` and the AI limits raised, because the audit opens hundreds of sessions): the `/control-room` page (empty, with a long-worded plan, the send form with its problems shown, after a provider failure) and the floating panel (open, plan tab, after a failure) at the viewport sizes given, in both themes and any languages. Each state gets the layout checks of `audit-matrix.cjs` (shared through `lib.cjs`) and axe-core. Found and fixed: a link inside a label (a second control in one target) and a `<header>` in the panel that counted as a second page banner. `--base --sizes --langs --themes [--no-axe] [--shots --out=<dir>]`; exit code 1 on any finding. |
| `audit-structure.cjs` | (PROMPT 15, no browser) Source files nothing reaches from an entry point (and files only a test reaches), dependencies nothing imports, hex colours written outside the token files, the five brand colours present in the tokens, environment variables read by the code but missing from `.env.example` (and the reverse). Exit 1 on an orphan or an unused dependency. |
| `audit-i18n.cjs` | (PROMPT 15) Every page × hu/en/nl in a real browser: raw localisation keys, unfilled placeholders (`undefined`, `{name}`, `[object Object]`, `NaN`) on screen or in an `aria-label`, `<html lang>`, an empty or key-like title, Hungarian/Dutch text **identical to the English** (a string that fell back or was never translated; names and technologies are allowed), and that the language switch leads to the equivalent page. |
| `audit-design.cjs` | (PROMPT 15) The five brand colours are the specified values in both themes, one typeface family, radii from the token list, the surface follows the theme, control sizes and names, on 10 pages × 2 sizes × 2 themes. |
| `audit-work.cjs` | The **Work page and the dynamic project page** (PROMPT 13.1), against a running backend. With an administrator's e-mail and password it first publishes three **stress projects** through the administration's API (a very long title, text and technology list; one with no picture and no page; one with a tall and a wide picture) and deletes them and their pictures at the end, so the layout meets what an owner might really write. Per language × theme × size it checks the Work page (also after choosing a category with the keyboard) and the stress project's pages for sideways scrolling, readable elements outside the viewport, targets under 24 px, controls without a name, one `h1`, pictures that did not load, empty headings, console errors and axe-core. `--base --email --password --sizes --themes --langs --out`; exit code 1 on any finding. Throw-away database only. |
| `audit-keyboard-strict.cjs` | (PROMPT 15) The quiet replacement for `audit-keyboard.cjs`: every control is numbered first (so "reached" is exact, a radio group is one stop), Tab walks until the order comes round, and a picture of the control **and its card** with and without focus says whether the ring is visible. Found the hero screenshot button's clipped ring. It does not walk the immersive Lab experience pages (React replaces their nodes, which drops the numbering): a plain Tab walk was used there. |
| `audit-lab-overlap.cjs` | (PROMPT 15) Every Lab experience × 3 languages × 7 sizes × reduced/normal motion: do the hint, the notice, the title, the crumb, the control panel or the dock lie on one another? Found the hint hidden under the notice on phones. |
| `webgl.cjs` | No WebGL at all, context loss and restore on the hero and a Lab experience, and which pages load Three.js. |
| `vitals.cjs`, `inp.cjs`, `timeline.cjs` | First/largest paint, layout shift and blocking time (CDP: 4× CPU slowdown, 150 ms / 1.6 Mbit/s for the phone profile); interaction latency from real clicks; where the time to first paint goes. |
| `mobile/` | (PROMPT 13.2) Phone checks with CDP touch events, emulated safe-area insets and CPU throttling: the intro and the Lab under a dragging finger, the notch, the hidden NFSU2 screen on phones, the quality governor end to end, the project pages' real picture widths, the administration on a notched phone. See `mobile/README.md`. `vitals.cjs` also has `--profile=phone-fast` and `--profile=phone-slow` (6× CPU, 400 kbit/s, 400 ms). |
| `devharness.cjs` | Starts a mock collector and the dev server with local endpoints: analytics consent, what an event may carry, the forms' success/failure/timeout handling, and a lazy page whose code fails to load. |
| `mapsize.cjs` | What is inside a bundle (`npx vite build --sourcemap --outDir /tmp/map --emptyOutDir`, then `node mapsize.cjs /tmp/map index-`). |

All of this is emulation in Chromium: no physical device, no Safari or Firefox, no screen reader.
