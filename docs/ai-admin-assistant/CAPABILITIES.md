# Capabilities

What the AI admin assistant can do, what it never does, and what is deliberately left out. Everything it states about the business comes from a tool result; the system prompt tells it not to state a figure, date, name, status, price or outcome that a tool did not return, and to say when it cannot verify something. (The prompt is the assistant's *conduct*; the boundaries that matter are enforced by the server whatever the model says — see [TOOL_SECURITY.md](TOOL_SECURITY.md).)

## What it can do

| | Capability | Tools | Reads | The rules |
| --- | --- | --- | --- | --- |
| **A** | Business overview | `getBusinessOverview`, `getBusinessActivity`, `getAdministrativeAlerts` | counts of quote requests, consultations, projects, tasks, conversations, customers | Every number says its period (`last_30_days`, `today`…) and whether it is a **period count** (`…InPeriod`) or a **state now** (`…Now`); `estimates: "none"`; a part the role may not read says "not available to you" and carries no number. Alerts come from fixed rules whose thresholds are in the answer ("status is *new* and the request is more than 2 days old"); an empty list means *no rule matched*, never "all clear" while a part was unavailable |
| **B** | Project intelligence | `searchAdminProjects`, `getAdminProjectDetails`, `summarizeProject`, `getProjectRisks`, `getProjectPendingActions` | projects, milestones, tasks, customer actions, approvals awaiting the customer, project events | **Stored status**, **stored task status**, **calculated progress** (the project module's own count, labelled `calculatedFromAllWork` / `shownToCustomer`) and **rule results** (`derived…`) are different fields. The assistant is told never to call anything completed unless the stored status says so. A risk list that is empty says "no rule triggered", not "no risk" |
| **C** | Quote intelligence | `searchAdminQuotes`, `getAdminQuoteDetails`, `summarizeQuoteRequest`, `compareQuoteRequests`, `prepareQuotationOutline` | quote requests, items, the brief, quotations with their **stored** figures, the customer's revision requests, history | Never invents a price or discount, never promises a delivery date, never accepts, rejects, sends, creates or edits a quotation (no tool does). A figure it repeats is the stored one (`storedTotals`, minor units). The outline is a **draft for human review**: no prices, no discounts, no dates (a draft containing an amount is refused by the server), not saved, not sent, marked "AI-generated draft: requires human review" |
| **D** | Customer intelligence | `searchAdminCustomers`, `getAdminCustomerOverview`, `getCustomerActivity` | stored customer fields, their projects, linked quote requests, consultations and conversations, one line per stored event | No e-mail address, phone, sign-in detail or note is returned. Nothing is inferred about a person: no tool returns anything but stored fields and counts, and the prompt forbids inferring character, finances, health or other personal attributes. A conversation about one customer reaches **only** that customer's records |
| **E** | Communication intelligence | `searchAdminConversations`, `getAdminConversation`, `summarizeConversation`, `draftCustomerReply`, `translateCustomerReply` | the customer-visible messages of a conversation, who wrote them, when, whether it waits for the owner | **A draft is not sent**: the tool returns `status: draft_not_sent`, `canBeSentFromHere: false`; the screen says "Draft only. Nothing has been sent." and links to the conversation page where the administrator sends it themselves. The reply language is the customer's preferred language (the tool tells the model which; a draft in another language is turned back unless the administrator asked for it). Private notes are never read. What the customer explicitly said and what the assistant assumes are separated by the fields (`possibleQuestionsFromCustomer` is labelled a heuristic) and by the prompt |
| **F** | Consultation intelligence | `searchAdminConsultations`, `getConsultationDetails`, `prepareConsultationBriefing` | bookings, proposed changes, history, scheduling conflicts computed from the booking data | Never changes availability or a booking, never cancels or reschedules (no tool). Reading a consultation does **not** run the booking list's "close expired proposals" (that writes); an expired proposal is *reported* as expired, and a test proves nothing was changed. Time is given as UTC instants with the zone it was scheduled in. The administrator's own notes on a booking are not read |
| **G** | Reports and the daily briefing | `generateDailyBriefing`, `generateProjectReport`, `generateBusinessReport`, `generateCustomerReport`, `generateQuoteReport`, `generateConversationReport`, `generateConsultationReport` | see [REPORTING.md](REPORTING.md) | **On demand only.** There is no scheduler, no background job and no e-mail: the briefing is built from stored records when an administrator asks |

Also: a conversation history per administrator (search, open, delete, "clear conversation"), suggested questions per context, copy and export of a summary, and copy / download / print of a report.

## What it will never do

It may read, analyse, summarise, compare, draft, prepare and recommend. It may **not**: create or modify customers; change project statuses; modify tasks, deadlines or milestones; create or modify quotations; accept or reject quotations; **send** customer messages; cancel or reschedule bookings; change customer permissions; delete records; change AI settings; change administrator permissions; touch billing or payment. Asked to, it says it can prepare the thing for human review but cannot execute it — an intentional security boundary — and says where in the administration the person does it. It never claims something was done when it only recommended it.

This is not a rule in the prompt that a clever message could talk it out of: **the tool set has no such tool**, the browser cannot add one, and a test (`aiAdminTools.test.ts`) takes a digest of every business table before and after running every tool in every context and requires it to be identical.

## What is deliberately not included

- **Private notes** (quote requests, inquiries, customers, projects, bookings, conversations) are not read. A draft reply could otherwise quote an internal note to a customer.
- **Attachments, file contents and URLs.** No tool opens a file or fetches an address.
- **Free search over message text.** Conversation search is by subject, reference and customer — not by the words of messages — so a search is not a way to read them.
- **Billing, payments, invoices.** None exist in the system; none are claimed.
- **Scheduled or proactive behaviour.** Nothing runs unless an administrator asks a question.
- **Action tools with a confirmation step.** The interface has confirmation dialogs (delete a conversation, clear a conversation), but there are no "approved actions" because nothing can be executed.
